Version 0.7.1 includes the [0.7.0 menus and asset mods](https://github.com/andrei-ace/atomic_bomberman/releases/tag/v0.7.0)
and fixes a prediction limit exposed by post-deployment WAN validation.

When host updates kept arriving slowly, the owner's clock could advance beyond
the 500 ms prediction window. Rebuilding from a delayed update then compressed
several movement steps into one visible step. Owner captures now stop at the
window until canonical progress allows another step. Bomb/action taps entered
while waiting retain their identities and apply once the window advances.

When a host update catches up with the owner's clock, prediction also retains
the owner's real pose instead of replacing it with the host's held-input
forecast. That retained pose still passes native collision validation against
the new shared world. A confirmed obstruction continues to correct it.

The failing WAN traces are retained with the release evidence. Deterministic
reproduction, queued-tap, host-catch-up and obstruction regressions cover the
fixes; the movement guard and its speed bounds are unchanged.

The diagnostic audit buffer now matches the existing frame window, so a valid
repair burst can be verified without overflowing the test-only audit queue.

This retains protocol **8** and compatibility family **0.7.0**. Existing private
server links, TLS identities, imported assets, settings and mods remain valid.
Update clients to 0.7.1 for the movement correction.

The five native packages are Windows x64 portable ZIP, Apple Silicon Mac ZIP,
Linux x86-64 AppImage, and Linux ARM64/amd64 relay archives, each with provenance
and a SHA-256 sidecar. Original game data and private server state are excluded.

Watch the [0.7.0 menus and mods demo](https://www.youtube.com/watch?v=kdETJWSwXpA)
and follow the [installation and play guide](https://github.com/andrei-ace/atomic_bomberman/blob/v0.7.1/README.md).
