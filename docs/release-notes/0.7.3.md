# 0.7.3

- Fix local-player snapping when delayed host updates catch the owner's clock
  and input changes between fixed captures. Prediction retains validated local
  motion across repeated rebuilds and keeps its active clock monotonic.
- Preserve the stopped avatar's idle pose when a host walking forecast reaches
  the same position. Position equality no longer substitutes for motion equality.
- Keep native collision and obstruction checks active during prediction recovery.
- Move stress-test snapshot comparisons to a bounded background worker so a
  delayed batch cannot block the other clients' gameplay consumers. All state,
  event and movement checks remain required; missing ticks and queue exhaustion
  fail validation, and the worker drains before reporting success.
- Add optional driver timing diagnostics to separate processing stalls from
  sleep overshoot during relay load tests.

The fixes apply to both Classic and HD graphics. Prepared HD artwork, imported
assets, mods, settings and private server links remain reusable. The HD cache
format, protocol 8 and the 0.7.0 compatibility family are unchanged; clients and
relays in that family remain compatible. Players should update their clients
to receive the movement fixes.

Two deterministic regressions reproduced the prediction defects before the
corrections. The network and game suites then passed 321 test executions,
including 1,056 seeded simulated games. Three ten-client WAN repetitions against
the existing 0.7.2 relay passed after the corrections, comparing 3,502, 3,504 and
3,503 committed ticks with zero application queue drops or send failures.
Matched relay forwarding p99 was 0.3ms in each run, while application RTT still
spiked near one second. These are headless production-session checks, not
physical display/input latency measurements. See the
[diagnosis and retained failures](https://github.com/andrei-ace/atomic_bomberman/blob/main/docs/wan-consistency.md#072-ten-client-wan-follow-up).
